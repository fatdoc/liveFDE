# 开发计划
按可验收里程碑推进，不凭空承诺工期。实际状态只在 project-team/STATUS.md。

| 阶段 | 交付门槛 |
|---|---|
| M0 工程基线 | 清晰目录、首次提交、worktree、Python/PG 启动、迁移、契约冻结 |
| M1 数据底座 | Admin、主播/场次、鉴权上传/Range、持久任务与重试，重启不丢数据 |
| M2 真分析 | FFmpeg→ASR→画面→证据→单场报告/候选，一场真实录像端到端与失败恢复 |
| M3 业务闭环 | 审核/学习资产/备播/周报/导出，现有所有页面接真实 API |
| M4 独立交付 | 浏览器验收、迁移/备份恢复、部署说明和版本，不依赖 CPB |
| M5 平台采集 | 抖音实际取流、视频号本地投屏、统一导入，非 V1 前置 |

## 窗口节奏
M0 一个工程窗口串行整理，独立只读审查后建基线。随后建议四窗口：统筹/集成、BE、AI、FE。
进入 Review 时启用独立审阅窗口，必要时替换空闲执行窗口；七个岗位不等于七个常驻进程。
共享数据库模型/迁移的后端任务串行；前端/AI 按冻结契约并行。

## 验收与样本
基础用小型合成 fixture；M2 需真实录像和模型账号，M3 周报需同主播多场。缺样本不阻塞基础 API，但不能宣布真实分析通过。
M5 每平台验证音画/时长/断流/地址过期/完成信号/重复导入；录制不等于取得订单和评论。
费用和性能以实测记录，未知写未知，付费失败不无限重试。
